## 通用数据帧
```
AA 55 | CMD | SEQ | LEN | TIME | Payload | CRC16
 2B      1B    1B    2B     4B     NB        2B
```

| 字段 | 类型 | 说明 |
|---|---|---|
| AA 55 | uint8[2] | 固定帧头 |
| CMD | uint8 | 命令类型 |
| SEQ | uint8 | 帧序号，0～255 循环 |
| LEN | uint16 | Payload 字节长度 |
| TIME | uint32 | 发送端运行时间，单位 ms |
| Payload | N 字节 | 业务数据 |
| CRC16 | uint16 | 校验码 |

总长度：12 + N 字节。
通信约定：
- UART：115200，8N1
- 字节序：Little Endian
- 最大 Payload：128 字节
- CRC：CRC-16/CCITT-FALSE
- CRC 多项式：0x1021
- CRC 初始值：0xFFFF
- CRC RefIn/RefOut：false
- CRC XorOut：0x0000
- 校验范围：CMD 至 Payload 末尾
- CRC 发送顺序：低字节在前

| CMD | 方向 | 名称 | Payload |
|---|---|---|---|
| 0x01 | Linux → ESP32 | 速度控制 | 6B |
| 0x02 | Linux → ESP32 | 停止运动 | 1B |
| 0x03 | Linux → ESP32 | 底盘使能 | 1B |
| 0x04 | Linux → ESP32 | 清除故障 | 0B |
| 0x05 | Linux → ESP32 | 心跳 | 0B |
| 0x06 | Linux → ESP32 | 设置反馈频率 | 6B |
| 0x07 | Linux → ESP32 | 获取设备信息 | 0B |
| 0x0A | Linux → ESP32 | 快速停止并禁能 | 0B |
| 0x81 | ESP32 → Linux | 四轮编码器及速度反馈 | 44B |

## Linux → ESP32 数据帧示例
### 示例 1：底盘速度控制（0x01）
Payload：

| 字段 | 类型 | 单位 | 示例 |
|---|---|---|---|
| vx | int16 | mm/s | 200 |
| vy | int16 | mm/s | 100 |
| wz | int16 | mrad/s | 300 |

正方向：前进 +X，左移 +Y，逆时针旋转 +Wz。
```
AA 55 | 01 | 01 | 06 00 | E8 03 00 00 | C8 00 64 00 2C 01 | 81 27
```
完整 HEX：
```
AA 55 01 01 06 00 E8 03 00 00 C8 00 64 00 2C 01 81 27
```
解析：
- C8 00：vx = 200 mm/s
- 64 00：vy = 100 mm/s
- 2C 01：wz = 300 mrad/s
CRC16 = 0x2781。
### 示例 2：速度归零（0x01）
三个速度均为 0。
```
AA 55 01 02 06 00 FC 03 00 00 00 00 00 00 00 00 7C A2
```
CRC16 = 0xA27C。
### 示例 3：正常停止（0x02）
Payload：

| 字段 | 类型 | 值 |
|---|---|---|
| stop_mode | uint8 | 0=正常减速；1=快速停车 |

```
AA 55 02 03 01 00 10 04 00 00 00 AA 60
```
CRC16 = 0x60AA。
### 示例 4：底盘使能（0x03）
Payload：

| 字段 | 类型 | 值 |
|---|---|---|
| enable | uint8 | 0=禁能；1=使能 |

```
AA 55 03 04 01 00 4C 04 00 00 01 A9 C2
```
表示启用底盘驱动。
CRC16 = 0xC2A9。
### 示例 5：清除故障（0x04）
无 Payload。
```
AA 55 04 07 00 00 78 05 00 00 51 0B
```
CRC16 = 0x0B51。
只能清除已经满足恢复条件的故障，不允许直接绕过硬件安全条件。
### 示例 6：心跳（0x05）
无 Payload。
```
AA 55 05 05 00 00 B0 04 00 00 36 2D
```
CRC16 = 0x2D36。
推荐发送周期：100 ms。
### 示例 7：设置数据反馈频率（0x06）
Payload：

| 字段 | 类型 | 示例 |
|---|---|---|
| wheel_hz | uint16 | 50 |
| imu_hz | uint16 | 50 |
| status_hz | uint16 | 2 |

```
AA 55 06 06 06 00 14 05 00 00 32 00 32 00 02 00 18 6B
```
解析：
- 32 00：车轮反馈 50 Hz
- 32 00：IMU 反馈 50 Hz
- 02 00：状态反馈 2 Hz
CRC16 = 0x6B18。
设置为 0 Hz 表示关闭该反馈流。
### 示例 8：查询设备信息（0x07）
无 Payload。
```
AA 55 07 08 00 00 DC 05 00 00 4A 69
```
CRC16 = 0x694A。
ESP32 收到后回复 0x85 设备信息。
### 示例 9：快速停止并禁能（0x0A）
无 Payload。
```
AA 55 0A 09 00 00 40 06 00 00 B2 57
```
CRC16 = 0x57B2。
立即请求停止电机输出并禁止驱动。该软件命令不能替代硬件急停。
## ESP32 → Linux 数据帧示例
### 示例 10：四轮编码器及速度反馈（0x81）
Payload：44 字节。

| 偏移 | 字段 | 类型 | 示例 |
|---|---|---|---|
| 0 | encoder_fl | int32 | 1200 |
| 4 | encoder_fr | int32 | 1180 |
| 8 | encoder_rl | int32 | 1190 |
| 12 | encoder_rr | int32 | 1210 |
| 16 | speed_fl | float32 | 5.0 rad/s |
| 20 | speed_fr | float32 | 5.0 rad/s |
| 24 | speed_rl | float32 | 5.0 rad/s |
| 28 | speed_rr | float32 | 5.0 rad/s |
| 32 | vx | float32 | 0.15 m/s |
| 36 | vy | float32 | 0 |
| 40 | wz | float32 | 0 |

顺序：左前 FL、右前 FR、左后 RL、右后 RR。
完整 HEX：
```
AA 55 81 21 2C 00 D0 07 00 00
B0 04 00 00 9C 04 00 00 A6 04 00 00 BA 04 00 00
00 00 A0 40 00 00 A0 40 00 00 A0 40 00 00 A0 40
9A 99 19 3E 00 00 00 00 00 00 00 00
1C 82
```
CRC16 = 0x821C。
以上换行为方便阅读，实际发送时字节连续排列。
编码器计数为累计计数。实际速度应根据编码器测量计算，不能直接复制目标速度。
### 示例 11：IMU 六轴数据（0x82）
Payload：24 字节。

| 偏移 | 字段 | 类型 | 示例 |
|---|---|---|---|
| 0 | ax | float32 | 0 |
| 4 | ay | float32 | 0 |
| 8 | az | float32 | 9.80665 |
| 12 | gx | float32 | 0 |
| 16 | gy | float32 | 0 |
| 20 | gz | float32 | 0.25 |

加速度单位为 m/s²；角速度单位为 rad/s。
完整 HEX：
```
AA 55 82 22 18 00 E4 07 00 00
00 00 00 00 00 00 00 00 0A E8 1C 41
00 00 00 00 00 00 00 00 00 00 80 3E
70 67
```
CRC16 = 0x6770。
这里的数值为六轴传感器经过量纲转换后的示例值，不是寄存器原始计数。
### 示例 12：底盘状态反馈（0x83）
Payload：16 字节。

| 偏移 | 字段 | 类型 | 示例 |
|---|---|---|---|
| 0 | state | uint8 | 2 |
| 1 | drive_enabled | uint8 | 1 |
| 2 | control_mode | uint8 | 0 |
| 3 | valid_flags | uint8 | 0x0E |
| 4 | fault_bits | uint32 | 0 |
| 8 | motor_fault_mask | uint16 | 0 |
| 10 | battery_mv | uint16 | 0 |
| 12 | last_cmd_seq | uint8 | 1 |
| 13 | reserved | uint8 | 0 |
| 14 | cmd_age_ms | uint16 | 20 |

完整 HEX：
```
AA 55 83 23 10 00 F8 07 00 00
02 01 00 0E 00 00 00 00 00 00 00 00 01 00 14 00
80 D8
```
CRC16 = 0xD880。
state 定义：

| 值 | 状态 |
|---|---|
| 0 | 禁能 |
| 1 | 已使能、待命 |
| 2 | 正在运动 |
| 3 | 正在停车 |
| 4 | 故障 |

valid_flags 位定义：

| Bit | 含义 |
|---|---|
| 0 | 电池电压有效 |
| 1 | 编码器有效 |
| 2 | IMU 有效 |
| 3 | STM32 通信正常 |

fault_bits 位定义：

| Bit | 故障 |
|---|---|
| 0 | 运动指令超时 |
| 1 | STM32 通信异常 |
| 2 | 电机驱动异常 |
| 3 | 编码器异常 |
| 4 | IMU 异常 |
| 5 | 电池欠压 |
| 6 | 硬件急停有效 |

motor_fault_mask 的 Bit 0～3 分别对应四个电机。
不存在对应检测硬件时，必须将其数据有效位置为 0。
### 示例 13：命令执行确认（0x84）
Payload：3 字节。

| 字段 | 类型 | 示例 |
|---|---|---|
| ack_cmd | uint8 | 0x03 |
| ack_seq | uint8 | 0x04 |
| result | uint8 | 0 |

完整 HEX：
```
AA 55 84 24 03 00 0C 08 00 00 03 04 00 23 7F
```
CRC16 = 0x7F23。
表示接受了 SEQ=4 的底盘使能命令。
result 定义：

| 值 | 含义 |
|---|---|
| 0 | 成功接受 |
| 1 | 长度错误 |
| 2 | 参数错误 |
| 3 | 设备忙 |
| 4 | 故障，拒绝执行 |
| 5 | 不支持的命令 |
| 6 | 当前状态不允许 |
| 7 | 安全条件不满足 |

### 示例 14：设备信息反馈（0x85）
Payload：8 字节。

| 字段 | 类型 | 示例 |
|---|---|---|
| protocol_version | uint8 | 1 |
| fw_major | uint8 | 1 |
| fw_minor | uint8 | 0 |
| fw_patch | uint8 | 0 |
| capability_flags | uint32 | 0x00000003 |

完整 HEX：
```
AA 55 85 25 08 00 20 08 00 00 01 01 00 00 03 00 00 00 FC A1
```
CRC16 = 0xA1FC。
capability_flags：
- Bit 0：支持四轮编码器反馈
- Bit 1：支持六轴 IMU
- Bit 2：支持电池检测
- Bit 3：支持硬件急停状态
- Bit 4：支持电机故障检测
## 默认发送周期

| CMD | 频率 |
|---|---|
| 0x01 速度指令 | 50 Hz |
| 0x05 心跳 | 10 Hz |
| 0x81 车轮反馈 | 50 Hz |
| 0x82 IMU 反馈 | 50 Hz |
| 0x83 状态反馈 | 2 Hz |
| 0x84 ACK | 按需 |
| 0x85 设备信息 | 按需 |

## 必要通信规则
1. Linux 和 ESP32 分别维护自己的 SEQ。
1. CMD 决定 Payload 的结构和预期长度。
1. CRC16 校验失败时直接丢弃数据帧。
1. LEN 超过 128 字节时拒绝接收。
1. 不支持的 CMD 不得执行。
1. 停止、使能、清除故障、配置频率等命令返回 ACK。
1. 速度控制指令不要求逐帧 ACK。
1. ESP32 连续 300 ms 未收到新的有效速度指令，应请求底盘停车；心跳不得延长旧速度的有效期。
1. STM32 必须另有独立的运动超时停车机制。
1. 通信异常、故障或设备重启后，不允许自动继续执行旧速度指令。
## 联调验收
- 能正确识别 AA 55 帧头。
- 能正确解析 uint16、int16、uint32、int32 和 float32。
- 所有示例帧通过 CRC 校验。
- 错误 CRC 帧不执行。
- 不完整帧不会造成解析器死锁。
- 速度指令能够正确执行。
- 四轮实际速度和编码器数据正确上报。
- IMU 六轴数据正确上报。
- 底盘使能、停止和故障状态正确反馈。
- 通信断开后能够安全停车。
